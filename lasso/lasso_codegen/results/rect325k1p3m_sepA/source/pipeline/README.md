# Full rectangular sparse-Lasso pipeline (sepA run)

Generates, verifies and benchmarks the sepA ISTA and FISTA solvers of this study. Scripts
live in `~/fomtools_full_pipeline` on Della; everything generated goes to `$ROOT` on scratch.
Settings come from `config.sh` and the `FOM_*` environment variables; this run used
`FOM_M=325000 FOM_N=1300000 FOM_VARIANT=sepA FOM_PROBLEM_DIR=<pipeline>/problems_v2
FOM_ISTA_TOL=1e-5 FOM_FISTA_TOL=1e-5` (the sepA problem files are `../paper_*_sparse20k.py`).

## Stages

1. `sepa_check.py` (CPU job): extracts both formulations with FOMTools and compares their
   reference executions (step size and iterates); the run stops if they differ.
2. `01_scaffold.sbatch` and `01b_cuda_objects.sbatch` (CPU jobs): extraction, OpenMP and
   CUDA scaffolds with shared verification data, deterministic objects, stub link tests.
3. `sepa_launch.sh` starts `controller_builtin.sh perjob` on the login node once 1 and 2
   are done. Per target: `workdir_guard.sh` (the target directory must hold only the
   scaffold), translation and code optimization through `fomtools_agent.py` (FOMTools'
   built-in instructions and default driver), independent verification after each phase, a
   fresh-build head-to-head in one job (code optimization kept unless more than 2% slower),
   final verification, and `provenance_check.py` (no copy of any other solver source, no
   reuse in the agent logs). Every `make` runs in a short Slurm job via `bridge/`.
4. `bench_supervisor.sh controller` (login node) waits for all four targets, copies in the
   original-form solvers (`ORIG_FROM`, `FOM_EXTRA_TARGETS`), runs `03_benchmark.sh prep`
   (rebuild, verify, checksum, baseline checks via `baselines.py`), then the seven rounds
   with each round holding the whole node (`bench_step.sbatch`; `BATCH_ROUNDS=1` runs the
   missing rounds back to back in one job), and finally `summarize.py`.
5. The original-form ISTA CUDA solver was generated by `controller_builtin.sh` in its own run
   directory (scaffold copied from the original-form run, `STOP_BEFORE_BENCHMARK=1`).
   `rebench_with_orig_ista_cuda.sh` waited for its final verification and provenance check,
   moved the earlier benchmark directory aside, copied the solver in as `orig_ista/cuda` and
   ran stage 4 again with all eight solvers; that second benchmark is the one archived here.

## Settings of the benchmark

`BASELINES=1` adds the hand-written SciPy and CuPy timings to every round;
`SERIES_VARIANT=sepA` labels the generated solvers in the summary; `FOM_BENCH_NODE=any`
lets prep pick a free AMD EPYC 7H12 + A100 node and pins all rounds to it.
