# Rectangular dense sparse-Lasso pipeline (sepA run, 10k by 40k, 260 nonzeros per row)

Generates, verifies and benchmarks the sepA ISTA and FISTA solvers of this study. Scripts
live in `~/fomtools_full_pipeline` on Della; everything generated goes to `$ROOT` on scratch.
Settings come from `config.sh` and the `FOM_*` environment variables; this run used
`FOM_M=10000 FOM_N=40000 FOM_K=260 FOM_VARIANT=sepA FOM_PROBLEM_DIR=<pipeline>/problems_v2
FOM_ISTA_TOL=1e-5 FOM_FISTA_TOL=1e-5 FOM_STEP_CONSTRAINT=a100` (the sepA problem files are
`../paper_*_sparse20k.py`).

## Stages

1. `01_scaffold.sbatch` and `01b_cuda_objects.sbatch` (CPU jobs): extraction, OpenMP and CUDA
   scaffolds with shared verification data, deterministic objects, stub link tests.
   `baseline_gate.sh` (CPU job) checks the hand-written SciPy iteration (`../baselines.py`)
   against the run's FOMTools reference execution and stops the run if they differ.
2. `gate_launch.sh` waits for stage 1 and the gate, then becomes `controller_builtin.sh perjob`
   on the login node. Per target: `workdir_guard.sh` (the target directory must hold only the
   scaffold), translation and code optimization through `fomtools_agent.py` (FOMTools'
   built-in instructions and default driver), independent verification after each phase, a
   fresh-build head-to-head in one job (code optimization kept unless more than 2% slower),
   final verification, `provenance_check.py` (no copy of any other solver source) and
   `transcript_check.py` (no agent tool call touching another run). Every `make` runs in a
   short Slurm job via `bridge/`.
3. The ISTA CUDA solver was generated by `controller_builtin.sh` in its own run directory from
   this run's fixed files, with `lock_others.py` making every other run's solver sources,
   reports and agent transcripts unreadable while the agent ran. Afterwards the files were
   restored, the provenance and transcript checks were rerun against all solvers, and the
   solver was copied into this run before the benchmark.
4. `bench_step.sbatch all` runs `03_benchmark.sh all` in one job: prep (rebuild, verify,
   checksum, baseline checks via `baselines.py`), the seven interleaved rounds and
   `summarize.py`.

## Settings of the benchmark

`BASELINES=1` adds the hand-written SciPy and CuPy timings to every round, with
`BASELINE_ORACLE=1 BASELINE_SKIP_FORM=1 BASELINE_TOL=1e-5` (the baselines are checked against
the FOMTools reference execution of this run; the original formulation is not built);
`SERIES_VARIANT=sepA` labels the generated solvers in the summary.
